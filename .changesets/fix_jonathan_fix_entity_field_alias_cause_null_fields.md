### fix: field aliases returning null on aliased connector entity fields ([PR #XXXX](https://github.com/apollographql/router/pull/9482))

The same alias-matching bug fixed for root query fields in #9358 also affected connector-backed entity fields. When an entity field was aliased and its sub-fields were also aliased, the sub-field aliases returned null — cascading into null propagation for non-nullable types. Either alias in isolation worked correctly; only the combination of both triggered the bug.

Given this `_entities` operation (generated by the query planner when a user aliases an entity field):

```graphql
query($representations: [_Any!]!) {
  _entities(representations: $representations) {
    ... on User {
      myProfile: profile {
        name
        pic: avatarUrl
      }
    }
  }
}
```

**Before**

Aliased sub-fields returned null, and null propagation cascaded through non-nullable types:

```json
{
  "_entities": [
    {
      "myProfile": {
        "name": null,
        "pic": null
      }
    }
  ]
}
```

**After**

Entity field aliases and sub-field aliases now work together as expected:

```json
{
  "_entities": [
    {
      "myProfile": {
        "name": "Foo",
        "pic": "https://example.com/foo.png"
      }
    }
  ]
}
```
